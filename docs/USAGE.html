自媒体发布插件 · 使用手册

用 agent 控制浏览器，把「搜狐号 / 头条号 / CSDN」的发布流程录制成可复用脚本；账号环境相互隔离，并按账号绑定各自的代理 IP。

已安装 0.4.7 10 个工具 9 条配置接口 638 项断言通过

0 · 先决条件：让插件真正加载起来

!
插件只在 DSH 启动时导入一次。改完文件、装完新版本，都必须重启 DeepSeek Harness 才会生效 —— 这一点我实测过五种进程内办法（切换 bundle、改 HMR 监视根、换真实副本、卸载重装、行级开关），全部无效。
  1. 安装或升级插件后，重启 DSH。
  2. 重启后确认版本：让我执行 media_config {op:"get"}，返回值里带 pluginVersion；或看设置页的插件卡片。
  3. 若报出的是更旧的版本（例如 0.3.4），说明还没重启到新版，账号管理相关界面不会出现。

1 · 三条使用路径

你想做的事走哪条路
改配置、管账号、登录GUI：设置 → 自媒体发布（或 设置 → Plugins → 自媒体发布）
让我（agent）直接发布对话：我用 media_* 工具完成

2 · GUI：设置 → 自媒体发布

页面有两个分区。发布环境是后端参数，发布账号是账号与登录管理。

2.1 发布环境

每项都显示当前值来自哪一层；被页面覆盖过的项会多出一个「恢复默认」按钮。

字段作用生效时机
pythonPath跑 Playwright 的解释器路径。留空＝自动探测 DSH 自带运行时 → PATH重启引擎
dataDir账号、登录态、recipe、回放的根目录。必须是绝对路径重启引擎
headless会话/回放默认是否无头。头条号会静默拦截无头发布，所以默认关下次调用
requireExplicitPublish真发时是否额外给「REAL PUBLISH」告警。真正的闸门是 dryRun 默认为 true，与本项无关下次调用
requestTimeoutMs单次引擎请求超时（1000–3600000）重启引擎
i
优先级：内置默认 ← 环境变量 ← 插件配置 cordis.patch.yml ← 你在页面保存的值（页面最高）。 值存在 ~/.dsh/media-publish/config.json。

2.2 发布账号

每个账号一行：代号 · 平台 · 登录名 · 登录状态 · 登录信息 · 代理。

按钮作用
登录打开一个有头浏览器窗口，请你在窗口里扫码。发起后请求立即返回，页面每 5 秒轮询，完成后自动变为「已登录」
检查校验已保存的登录是否仍有效。这是只读校验、不回写登录态，所以不会弄坏一个好登录
编辑把该账号填进下方表单（代号/平台/登录名/备注），改完「保存账号」
代理展开代理表单：填 代理服务器 / 用户名 / 密码 → 绑定；或解绑；或测试（显示出口 IP 与耗时）
删除删除账号，保留已保存的登录态
删除并退出登录删除账号，并删除登录态（会二次确认）

下方表单可新增账号：代号（1–32 位字母数字与 . _ -，首字符须为字母或数字）、平台、登录名、备注。

登录信息如何保留，以及账号之间如何隔离

  • 登录信息保存在每个账号自己的文件里：<dataDir>/accounts/<代号>/storage_state.json（cookies + localStorage）。 页面上的「登录信息已保存：12.3KB」就是直接读该文件得到的字节数，不是估计值。
  • 除登录态外，每个账号还有独立的浏览器上下文、独立指纹（由代号确定性派生：UA / 平台 / 视口 / 时区 / DPR / GPU，同账号永远一致、不同账号必然不同）、独立的代理绑定。
  • 因此 a-1 的登录态对 b-1 不可见；b-1 目录下不会出现 a-1 的文件。这一条有回归测试锁定：两个账号的状态文件路径必须不同。
  • 代理密码只进不出：绑定时代码把密码交给引擎，引擎写进 secrets.yaml；之后所有接口只回 hasPassword: true/false，永不回显。有测试用真实密码串 grep 整个响应来锁死这一点。

3 · 对话：让我直接干活

你只需说人话，我来选工具。以下是常用对照：

你说我调用
看看插件状态media_status（加 probe:true 会真启动引擎验证 Playwright）
列出账号media_account {op:"list"}
给 a-1 登录media_account {op:"login", code:"a-1"}（弹窗等你扫码，最长等 10 分钟）
检查登录还有效吗media_account {op:"check", code:"a-1"}
给 b-1 绑代理media_account {op:"bindProxy", code:"b-1", proxy:{…}}
读 / 改配置media_config {op:"get" | "set" | "reset"}
用搜狐号发这篇（先空跑）media_publish {op:"run", recipeId, accountCode, params:{title, body}}
✓
安全默认：dryRun 默认为 true。空跑会打开页面、填表、截图，但跳过提交。 真正发布必须显式传 dryRun:false。这条有测试用真实提交次数锁定（不传 dryRun → 提交 0 次）。

4 · 录制 → 编译 → 回放（核心价值）

4.1 第一次：录一段真实流程

  1. 我打开会话：media_session {op:"open", accountCode:"a-1"}
  2. 开始录制：media_record {op:"start", sessionId, media:"sohu", recipeId:"sohu__my-flow"}
  3. 我逐步操作（media_observe 看页面元素与截图 → media_act 点击/输入/选择/上传…），你在窗口里只处理扫码或验证码
  4. 保存：media_record {op:"save", sessionId, label:"搜狐号发布图文"} —— 会把标题、正文等字面量自动参数化成 {{title}} / {{body}}，并产出一份 compile-report 告诉你哪些字面量变成了参数、哪一步被当作提交步骤
!
三份内置 recipe 已随插件提供（搜狐 14 步 / 头条 26 步 / CSDN 17 步），它们的登录守卫已对三个真实平台确证 —— 未登录时会在敲任何内容之前以 LOGIN_REQUIRED 快速失败。但正文 / 标签 / 封面等内容步骤尚未对真机确证， 这正是需要你登录后录一次来校准的部分。

4.2 之后：一句话回放

media_publish {op:"run", recipeId:"sohu__my-flow", accountCode:"a-1",
               params:{title:"标题", body:"正文"}, dryRun:true}    ← 先空跑，看截图

media_publish {op:"run", recipeId:"sohu__my-flow", accountCode:"a-1",
               params:{title:"标题", body:"正文"}, dryRun:false}   ← 确认后真发

media_publish {op:"backfill", accountCode:"a-1", title:"标题"}      ← 平台审核完后取正式链接

回放会自愈：某一步定位器失效，先重新快照并寻找候选；只有唯一高置信才改写，有歧义就报错并把候选交给你。 每次运行都会在 <dataDir>/runs/<时间>-<recipe>-<账号>/ 留下 run.json 与逐步截图。

5 · 数据在哪

路径内容
accounts/<代号>/storage_state.json该账号的登录信息（隔离的关键）
accounts.yaml账号登记表
proxies.yaml静态代理列表与提取器配置
secrets.yaml代理密码（从不回显）
recipes/<平台>/<id>.yaml你录制的 recipe（优先于内置同名 recipe）
runs/…每次回放的 run.json 与截图
config.json页面上保存的五个参数

默认根目录：%USERPROFILE%\.dsh\media-publish

6 · 出问题看这里

现象原因与处理
设置里没有「自媒体发布」还没重启 DSH，或 live 版本低于 0.3.5
页面提示「本部署的 web 服务上没有注册插件的配置路由」旧版本的路由注册缺陷（≤ 0.3.3）。升级并重启
页面提示「插件拒绝了这些取值」请求被拒。看括号里的 HTTP 码：409 ＝ 有其他写入方改了配置，点「重新读取」再存
LOGIN_REQUIRED该账号没有可用登录态 → 在页面上点「登录」扫码
PROXY_UNAVAILABLE代理不可用。这不是登录失效，插件不会把它伪装成登录过期
NAVIGATION_FAILED页面跳转失败或被中断。返回里带 requestedUrl / finalUrl / reason
TARGET_NOT_FOUND定位器失效。返回里带候选元素，可据此修 recipe 或重录该段
头条号发布失败头条会拦截无头发布。确保 headless=false（本插件默认就是）

7 · 当前边界（诚实清单）

✕
内置 recipe 的内容步骤未对真机确证。登录守卫已确证；正文 / 标签 / 封面需要你登录后各录一次来校准。
✕
动态代理池的提取链接不能从页面配置。引擎只暴露 proxy.fetch / proxy.test / proxy.rotate， 没有读写 proxies.yaml 提取器的接口。页面目前支持的是每账号绑定固定代理。 要接提取器需要给引擎加一个配置接口（可以加，需要你提供链接与返回格式）。
!
登录必须人工扫码。页面上的「登录」会打开窗口等你操作 —— 这是平台的验证机制，无法自动化绕过。
!
改绑代理会改变出口 IP。登录态仍在，但对绑定 IP 的平台可能触发二次验证。建议先定代理再登录。
!
若某平台把会话绑在 cookie / localStorage 之外（IndexedDB、Service Worker），storage_state 不覆盖这部分。 目前未观察到这类情况，但也未对三平台长期登录寿命做过验证。

8 · 最短上手路径

  1. 重启 DSH，然后让我确认 pluginVersion 是 0.4.7。
  2. 进入 设置 → 自媒体发布 → 发布账号，点 a-1 的「登录」，扫码，等页面显示「已登录」。
  3. 告诉我一声，我会立刻验证三件事：media_account {op:"check", code:"a-1"} 是否有效； accounts/a-1/storage_state.json 是否真的存在且含 cookies；accounts/b-1/ 下是否仍然为空（隔离证据）。
  4. 然后我们录一次真实的搜狐号发布，把内置 recipe 的内容步骤校准到能用。
  5. 之后你只要说「用搜狐号发这篇：标题… 正文…」，我先空跑给你看截图，你确认后真发。
