# 自媒体发布插件 · 使用手册

本手册对应当前代码（**0.4.7**）。里面每条都区分了「已验证」与「尚未对真机确证」，请照着看，不要假设更多。

---

## 0. 先决条件：让插件真正加载起来

插件的宿主半**只在 DSH 启动时导入一次**，之后改文件不会生效（这一点我实测过五种进程内办法，全部无效）。所以：

1. 安装/升级插件后**必须重启 DeepSeek Harness**；
2. 重启后确认版本 —— 让我执行 `media_status`，或直接看设置页里的插件卡片；
3. 当前已安装版本是 **0.4.7**；如果你的 `media_status` 报的是更旧的版本（例如 0.3.4），说明**还没重启到新版**，账号管理相关的界面不会出现。

判断版本最直接的办法：让我调用 `media_config {op:"get"}`，返回值里带 `pluginVersion`。

## 1. 三条使用路径

| 你想做的事 | 走哪条路 |
|---|---|
| 改配置、管账号、登录 | **GUI**：设置 → 自媒体发布（或设置 → Plugins → 自媒体发布） |

## 2. GUI：设置 → 自媒体发布

页面有两个分区。

### 2.1 发布环境

五个后端参数，每项都显示**当前值来自哪一层**，被覆盖的项有「恢复默认」按钮：

| 字段 | 作用 | 生效时机 |
|---|---|---|
| `pythonPath` | 跑 Playwright 的解释器路径。留空＝自动探测 DSH 自带运行时 → PATH | 重启引擎 |
| `dataDir` | 账号、登录态、recipe、回放的根目录。必须是绝对路径 | 重启引擎 |
| `headless` | 会话/回放**默认**是否无头。头条号会静默拦截无头发布，所以默认关 | 下次调用 |
| `requireExplicitPublish` | 真发时是否额外给「REAL PUBLISH」告警。**真正的闸门是 `dryRun` 默认为 true**，与本项无关 | 下次调用 |
| `requestTimeoutMs` | 单次引擎请求超时（1000–3600000） | 重启引擎 |

优先级：**内置默认 ← 环境变量 ← `cordis.patch.yml` ← 你在页面上保存的值**（页面最高）。值存在 `~/.dsh/media-publish/config.json`。

> `pythonPath` 与 `dataDir` 会影响引擎进程，所以保存后我会关闭当前引擎，下次调用自动用新配置启动。

### 2.2 发布账号

每个账号一行：`代号 · 平台 · 登录名 · 登录状态 · 登录信息 · 代理`，行尾按钮：

| 按钮 | 作用 |
|---|---|
| **登录** | 打开一个**有头浏览器窗口**，请你在窗口里扫码/输密码。**发起后请求立即返回**，页面每 5 秒轮询，完成后自动变为「已登录」 |
| **检查** | 校验已保存的登录是否仍有效。这是**只读校验，不回写**登录态，所以不会弄坏一个好登录 |
| **编辑** | 把该账号填进下方表单（代号/平台/登录名/备注），改完「保存账号」 |
| **代理** | 展开代理表单：填 `代理服务器 / 用户名 / 密码` → **绑定**；或**解绑**；或**测试**（显示出口 IP 与耗时） |
| **删除** | 删除账号，**保留**已保存的登录态 |
| **删除并退出登录** | 删除账号，**并**删除登录态（会二次确认） |

下方表单可**新增账号**：代号（1–32 位字母数字 `.` `_` `-`，首字符须为字母或数字）、平台（搜狐号/头条号/CSDN）、登录名、备注。

**关于登录与隔离**（这是设计核心，也是你之前最关心的两点）：

- 登录信息保存在**每个账号自己的文件**里：`<dataDir>/accounts/<代号>/storage_state.json`（cookies + localStorage）。页面显示的「登录信息已保存：12.3KB」就是**直接读该文件**得到的字节数，不是估计值。
- 除登录态外，每个账号还有**独立的浏览器上下文、独立指纹**（由代号确定性派生：UA/平台/视口/时区/DPR/GPU，同账号永远一致、不同账号必然不同）、**独立的代理绑定**。
- 因此：**a-1 的登录态对 b-1 不可见**；`b-1` 目录下不会出现 `a-1` 的文件。这一条有专门的回归测试（两个账号的状态文件路径必须不同）。
- **代理密码只进不出**：绑定时代码把密码交给引擎，引擎写进 `secrets.yaml`；之后所有接口只回 `hasPassword: true/false`，永不回显。有测试用真实密码串 grep 整个响应来锁死这一点。

## 3. 对话：让我直接干活

常用指令（你只需说人话，我来选工具）：

- 「看看插件状态」→ `media_status`（加 `probe:true` 会真启动引擎验证 Playwright）
- 「列出账号」→ `media_account {op:"list"}`
- 「给 a-1 登录」→ `media_account {op:"login", code:"a-1"}`（会弹窗等你扫码，最长等 10 分钟）
- 「检查 a-1 登录还有效吗」→ `media_account {op:"check", code:"a-1"}`
- 「把 b-1 绑到 http://ip:port」→ `media_account {op:"bindProxy", code:"b-1", proxy:{...}}`
- 「读/改配置」→ `media_config {op:"get"|"set"|"reset"}`
- 「用搜狐号发这篇（先空跑）」→ `media_publish {op:"run", recipeId:"sohu__publish-article", accountCode:"a-1", params:{title, body}}`

**安全默认**：`media_publish` 的 `dryRun` **默认为 true** —— 会打开页面、填表、截图，但**跳过提交**。真正发布必须显式 `dryRun:false`。这一条有测试用**真实提交次数**锁定（不传 dryRun → 提交 0 次）。

## 4. 录制 → 编译 → 回放（本插件的核心价值）

### 4.1 第一次：录一段真实流程

1. 我打开会话：`media_session {op:"open", accountCode:"a-1"}`
2. 开始录制：`media_record {op:"start", sessionId, media:"sohu", recipeId:"sohu__my-flow"}`
3. 我逐步操作（观察页面 → 点击/输入/选择/上传…），你在窗口里只处理扫码/验证码：
   - `media_observe` 看页面可交互元素与截图
   - `media_act {action:{type:"click", target:{text:"发布"}}}` 等
4. 保存：`media_record {op:"save", sessionId, label:"搜狐号发布图文"}` —— 会把标题/正文等**字面量自动参数化成 `{{title}}`/`{{body}}`**，并产出 compile-report 告诉你哪些字面量变成了参数、哪一步被当作提交步骤。

> 三份**内置 recipe** 已随插件提供（sohu 14 步 / toutiao 26 步 / csdn 17 步），它们的**登录守卫已对三个真实平台确证**（未登录时会在敲任何内容前以 `LOGIN_REQUIRED` 快速失败），但**正文/标签/封面等内容步骤尚未对真机确证** —— 这正是需要第一次录制来校准的部分。

### 4.2 之后：一句话回放

```
media_publish {op:"run", recipeId:"sohu__my-flow", accountCode:"a-1",
               params:{title:"标题", body:"正文"}, dryRun:true}     ← 先空跑
media_publish {op:"run", recipeId:"sohu__my-flow", accountCode:"a-1",
               params:{title:"标题", body:"正文"}, dryRun:false}    ← 确认后真发
media_publish {op:"backfill", accountCode:"a-1", title:"标题"}       ← 平台审核完后取正式链接
```

回放时会**自愈**：某一步定位器失效，先重新快照并找候选；只有唯一高置信才改写，有歧义就报错并把候选给你。每次运行都会在 `<dataDir>/runs/<时间>-<recipe>-<账号>/` 留下 `run.json` 与逐步截图。

## 5. 数据在哪

| 路径 | 内容 |
|---|---|
| `<dataDir>/accounts/<代号>/storage_state.json` | 该账号的登录信息（隔离的关键） |
| `<dataDir>/accounts.yaml` | 账号登记表 |
| `<dataDir>/proxies.yaml` | 静态代理列表与**提取器**配置 |
| `<dataDir>/secrets.yaml` | 代理密码（**从不回显**） |
| `<dataDir>/recipes/<平台>/<id>.yaml` | 你录制的 recipe（**优先于**内置同名 recipe） |
| `<dataDir>/runs/…` | 每次回放的 run.json 与截图 |
| `<dataDir>/config.json` | 页面上保存的五个参数 |

默认 `<dataDir>` = `%USERPROFILE%\.dsh\media-publish`。

## 6. 出问题看这里

| 现象 | 原因与处理 |
|---|---|
| 设置里没有「自媒体发布」 | 还没重启 DSH，或 live 版本低于 0.3.5 |
| 页面显示「本部署的 web 服务上没有注册插件的配置路由」 | 旧版本（≤0.3.3 的路由注册缺陷）。升级并重启 |
| 页面显示「插件拒绝了这些取值」 | 请求被拒。看括号里的 HTTP 码：409＝有其他写入方改了配置，点「重新读取」再存 |
| `LOGIN_REQUIRED` | 该账号没有可用登录态 → 在页面上点「登录」扫码 |
| `PROXY_UNAVAILABLE` | 代理不可用。**这不是登录失效**，插件不会把它伪装成登录过期 |
| `NAVIGATION_FAILED` | 页面跳转失败/被中断。返回里带 `requestedUrl`/`finalUrl`/`reason` |
| `TARGET_NOT_FOUND` | 定位器失效。返回里带候选元素，可据此修 recipe 或重录该段 |
| 头条号发布失败 | 头条会拦截无头发布。确保 `headless=false`（本插件默认就是） |

## 7. 当前边界（诚实清单）

1. **三份内置 recipe 的内容步骤未对真机确证** —— 登录守卫已确证；正文/标签/封面需要你登录后各录一次来校准。
2. **动态代理池的提取链接不能从页面配置** —— 引擎只暴露 `proxy.fetch/test/rotate`，**没有**读写 `proxies.yaml` 提取器的接口。页面目前支持的是**每账号绑定固定代理**。要接提取器需给引擎加一个配置 RPC（可以加，需要你给链接与返回格式）。
3. **登录必须人工扫码** —— 页面上的「登录」会打开窗口等你操作；这是平台的验证机制，无法自动化绕过。
4. **账号改绑代理会改变出口 IP**，登录态仍在，但对绑 IP 的平台可能触发二次验证。建议**先定代理再登录**。
5. 若某平台把会话绑在 localStorage/cookie 之外（IndexedDB、Service Worker），`storage_state` 不覆盖这部分 —— 目前**未观察到**这类情况，但也未对三平台长期登录寿命做过验证。

## 8. 最短上手路径（建议按这个顺序）

1. **重启 DSH** → 让我确认 `pluginVersion` 是 0.4.7。
2. **设置 → 自媒体发布 → 发布账号** → 点 **a-1 的「登录」** → 扫码 → 等页面显示「已登录」。
3. 告诉我一声，我会立刻验证：`media_account {op:"check", code:"a-1"}` 是否有效、`accounts/a-1/storage_state.json` 是否真的存在且含 cookies、以及 `accounts/b-1/` 下是否**仍然为空**（隔离证据）。
4. 然后我们**录一次真实的搜狐号发布**，把内置 recipe 的内容步骤校准到能用。
5. 之后你只要说「用搜狐号发这篇：标题…正文…」，我先空跑给你看截图，确认后真发。
